# Notification update — scope and deployment
Existing notification API, roles and permission checks retained. Added explicit customer events for account changes, password changes/reset, social signup, email verification, KYC upload/submission/decision, manual plan assignment, shipment update/tracking/document deletion, and staff account changes. Added plan and role management alerts, notice publication for currently published notices, and staff mutation/403 audit alerts. Existing customer notification page is shared by all three dashboards; new category and email queue state are displayed. Email accepted is not inbox delivery.

Staff audit alerts describe HTTP outcomes, not guaranteed business commits. Explicit controller events suppress the generic staff alert in selected paths. Existing other events may still produce both a business alert and a staff audit alert. Logout is a client sign-out audit endpoint, not token revocation. Closed tabs and expired sessions do not generate logout events.

Not completed: device/suspicious login detection, dedicated payment failure/refund/bank transfer/invoice lifecycle, quota thresholds, scheduled notice dispatch, document expiry, shipment delay automation, support assignment/priority, report deletion/ready, detailed permission diff, email retry UI and full event deduplication. Existing subscription reminder worker still requires cron. No new business workflow was fabricated. Live MongoDB, SMTP/Brevo, and production frontend build not tested.
